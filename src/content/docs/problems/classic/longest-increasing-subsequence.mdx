## 题目

给一个整数列表 `nums`，返回最长严格递增子序列的长度。

- 子序列可以不连续，但要保持原来的先后顺序：从 `[10, 9, 2, 5]` 里挑出 `2, 5` 是子序列，`5, 2` 不是。
- 严格递增：后一个数必须大于前一个，相等不算。
- 元素可以是负数，也可以重复。空列表返回 0。
- 时间复杂度要求 O(n log n)，n 是列表长度。

## 样例

| 输入 | 输出 | 说明 |
|---|---|---|
| `[10, 9, 2, 5, 3, 7, 101, 18]` | `4` | 例如 `2, 3, 7, 18` |
| `[2, 2, 2]` | `1` | 相等不算递增 |
| `[3, 4, 1]` | `2` | `3, 4` |
| `[]` | `0` | 空列表 |

第一个样例的最长子序列不止一条，`2, 5, 7, 101` 也是长度 4，题目只要长度。

`[2, 2, 2]` 抓二分边界写错：把“第一个 ≥ x”写成“第一个 > x”，会得到 3。`[3, 4, 1]` 说明另一件事：算法最后留下的数组是 `[1, 4]`，它不是真实的子序列，但长度 2 是对的。

## 思路

每个长度只记一个数：这个长度的递增子序列最小能以几结尾。这些数排成递增数组 `tails`。每读一个数，二分找到它的位置，替换或追加。最后 `tails` 的长度就是答案。

直接的 DP 是：`f[i]` 表示以 `nums[i]` 结尾的最长递增子序列长度，每个 `i` 回头看所有比它小的 `nums[j]`，取 `f[j] + 1` 的最大值，O(n²)。

读到 `[10, 9, 2, 5]` 时，长度 1 的递增子序列有 `10`、`9`、`2`、`5` 四条。最值得留的是结尾最小的 `2`：后面来一个 3，能接在 2 后面，接不到 10、9、5 后面。所以每个长度只需记住能做到的最小结尾。

`tails[k]` 是长度为 k + 1 的递增子序列里最小的结尾值。读完 `[10, 9, 2, 5, 3]` 时 `tails = [2, 3]`：长度 1 最小以 2 结尾，长度 2 最小以 3 结尾（`2, 3`），还没有长度 3。

读进新数 `x` 时，设 `p` 是 `tails` 里第一个 ≥ `x` 的位置：

- `p` 之前的结尾都比 `x` 小，`x` 能接在长度 `p` 的子序列后面，得到长度 `p + 1`、以 `x` 结尾的子序列。
- `tails[p] ≥ x`，换成 `x` 不会更差，于是 `tails[p] = x`。
- 所有结尾都比 `x` 小时，`p` 等于 `tails` 的长度，追加 `x`，最长长度加 1。

`tails` 始终严格递增。一条长度 3 的子序列去掉最后一个数，就是一条结尾更小的长度 2 子序列，所以长度 3 的最小结尾一定大于长度 2 的。数组有序，`p` 就能二分查找，每个数 O(log n)。

`tails` 的长度是可靠的：位置 `k` 上有值，就真的存在一条长度 `k + 1` 的递增子序列。所以最后返回 `len(tails)`。

<Solution slug="longest-increasing-subsequence" />

两个版本都手写了 `lower_bound`，返回第一个 ≥ `x` 的位置。Python 标准库里的 `bisect.bisect_left(tails, x)` 做的是同一件事，可以直接替换；TypeScript 没有内置的二分查找，只能手写。`lo < hi`、`lo = mid + 1`、`hi = mid` 这三处任何一处写成别的形式，都容易死循环或差一位，建议记住这一种写法。

TypeScript 里用 `(lo + hi) >> 1` 取中点。位运算会把数转成 32 位整数，这里 `hi` 不超过列表长度，不会溢出。

## 复杂度

n 是 `nums` 的长度，L 是答案（最长递增子序列的长度），L ≤ n。

- **时间 O(n log L)**，也就是 O(n log n)：每个数做一次二分查找，`tails` 最长 L，一次查找最多比较 ⌈log₂(L + 1)⌉ 次，之后的追加或替换是 O(1)。
- **空间 O(L)**：只存 `tails`。

## 自测：相等元素和非递减

<Aside type="caution" title="二分的边界决定了“严格”还是“不严格”">
`[2, 2, 2]` 的正确答案是 1。读第二个 2 时，第一个 ≥ 2 的位置是 0，把 2 换成 2，长度不变。如果你得到 3，说明二分找的是“第一个 > x”的位置（相当于 `bisect_right`），相等的数被当成了可以接上。

反过来，如果题目要的是**非递减**子序列（允许相等），正确做法恰好就是改用“第一个 > x”，`[2, 2, 2]` 的答案变成 3。

`[0, 1, 0, 3, 2, 3]` 的正确答案是 4（`0, 1, 2, 3`）。读到 2 时要把 3 替换掉，`tails` 从 `[0, 1, 3]` 变成 `[0, 1, 2]`，后面的 3 才能接上。如果你得到 3，检查替换时下标是否差了一位。
</Aside>

## 延伸：要输出一条最长的子序列呢？

`tails` 不能直接拿来当答案，`[3, 4, 1]` 已经说明了这一点。要多记两样东西：

- `tail_idx[k]`：`tails[k]` 这个值在 `nums` 里的下标。
- `parent[i]`：`nums[i]` 放进 `tails` 时接在谁后面。它放在位置 `p`，前一个就是“当时长度 `p` 的最佳结尾”，即 `tail_idx[p - 1]`；`p = 0` 时没有前驱，记 −1。

读完之后，从 `tail_idx` 的最后一项出发，沿着 `parent` 倒着走，再反转一次就是答案。二分和替换的逻辑一行不改，时间仍是 O(n log n)，多出的 `parent` 占 O(n) 空间。

`parent` 记的是放入那一刻的前驱，之后 `tails` 再被改写也不影响它。`[3, 4, 1]` 里，1 放进位置 0 时把 `tail_idx[0]` 改成了 1 的下标，但 4 的 `parent` 早已记下 3 的下标 0，所以输出是 `[3, 4]`，不会被 1 带偏。

最长递增子序列可能不止一条，样例里 `2, 5, 7, 101`、`2, 3, 7, 18` 都对。这段代码从最后一个长度的最小结尾往回走，返回的是 `[2, 3, 7, 18]`。本页的测试用 O(n²) DP 在 500 组随机输入上对拍，检查长度一致，并检查输出的确是原列表的严格递增子序列。
