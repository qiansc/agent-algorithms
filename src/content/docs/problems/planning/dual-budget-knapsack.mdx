## 题目

从 n 个相互独立的验证分支里挑一些来跑，调用次数和 token 都不能超预算，求最高总分。

- 输入：分支 i 是 `[calls, tokens, value]`，跑一次消耗 calls 次工具调用、tokens 单位 token，得 value 分。每个分支最多跑一次，得分相加。
- 预算：最多 `call_cap` 次调用、`token_cap` 单位 token。一个都不跑得 0。
- token 已经换算成整数单位，例如一单位表示 100 个 token。
- calls、tokens、value 都是正整数；两个上限是非负整数。不满足时抛出异常。
- 规模：n ≤ 80，`call_cap` ≤ 30，`token_cap` ≤ 200。

## 样例

`branches = [[2,4,9], [1,3,6], [1,2,5]]`，依次叫作 A、B、C。

| call_cap | token_cap | 输出 | 说明 |
|---|---|---|---|
| 2 | 5 | `11` | 跑 B 和 C：2 次调用、5 单位 token，6 + 5 |
| 2 | 4 | `9` | B + C 要 5 单位 token，超了；只能跑 A |

A 单个分数最高，但第一行跑了 A 就没余量了，B 和 C 合起来有 11。第二行专门卡“预算正着扫”：那样 C 会跑两遍，答成 10。

## 思路

这是有两种容量的 0/1 背包：用一张二维表，每看一个分支就把两个预算都从大往小扫一遍。0/1 指每件物品只能拿或不拿，不能拿两次。

`best[c][t]` 表示在已看过的分支里，最多用 c 次调用、t 单位 token 的最高分。一开始全是 0。每看一个分支（耗费 calls、tokens，得 value 分），就把每格更新一次：

- 不跑它：分不变。
- 跑它：留给之前分支的预算是 (c − calls, t − tokens)，取那格的分加 value。

两者取大。看完所有分支，`best[call_cap][token_cap]` 就是答案。

为什么要从大往小扫？转移读的是更小预算的那格，它必须还没算上当前分支。只用一张表时，正着扫会先改小格子，大格子再读它，等于把这个分支又跑了一次。上面的反例里，(1, 2) 先变成 5，(2, 4) 读到它再加 5，得 10。

倒着扫时大格子先算，读到的小格子还是上一轮的值；小格子后改，之后没有格子再读它。

两维都倒着扫最稳妥。严格说，每个分支至少 1 次调用，读的格子一定在更小的 c 那一行，只要 c 倒着扫，t 怎么扫都行。但如果允许调用次数为 0，就只能靠 t 倒序保护。两维都倒序，不用分情况。

建二维表时，两种语言有同一个坑。Python 的 `[[0] * (T + 1)] * (C + 1)` 和 TypeScript 的 `new Array(C + 1).fill(new Array(T + 1).fill(0))` 都只建了**一行**，其余各行是同一个对象的引用，改一格会改动整列。所以 Python 用列表推导式，TypeScript 用 `Array.from({ length }, () => ...)`，每次回调都新建一行。

## 复杂度

n 是分支个数，C 是 `call_cap`，T 是 `token_cap`。

- **时间 O(n·C·T)**：每个分支把整张 (C + 1) × (T + 1) 的表扫一遍。按题目上限约是 80 × 31 × 201，五十万次左右。
- **空间 O(C·T)**：只有一张表。

这个复杂度依赖预算的数值，而不是输入的长度。T 如果是几百万，输入里只是一个几字节的整数，表却要几百万格乘以 C，得先算一下内存放不放得下。

## 延伸：两项预算必须恰好用完呢？

比如这批验证要正好占满分配到的调用次数和 token，不允许剩。

转移不变，改的是初值和含义：`best[c][t]` 改成**恰好**用掉 c 次调用、t 单位 token 的最高分。只有 `best[0][0]` 是 0，其余格子初值是负无穷，表示凑不出来。负无穷加任何分数仍是负无穷，不会被误用。最后 `best[call_cap][token_cap]` 还是负无穷，就返回 −1。

为什么不能用全 0 初值？全 0 等于说“什么都不跑也能恰好用掉 (c, t)”。拿样例和预算 (1, 4) 来看：1 次调用的分支只有 B (1, 3) 和 C (1, 2)，凑不出恰好 4 单位 token，正确答案是 −1。全 0 初值却会从 `best[0][1] = 0` 转移出 0 + 6 = 6，把剩下的 1 单位 token 也算作花掉了。

样例的预算 (2, 5) 恰好由 B + C 用完，答案仍是 11；(2, 4) 恰好由 A 用完，答案仍是 9。
