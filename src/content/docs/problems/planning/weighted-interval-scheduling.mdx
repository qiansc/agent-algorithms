export const toneFor = (s) => (j) => {
  const k = ordered.indexOf(j);
  if (s.i < 0) return 'default';
  if (k === s.i) return s.wrong ? 'warn' : 'strong';
  if (k > s.i) return 'ghost';
  if (s.wrong && k === 1) return 'warn';
  return k < s.eligible ? 'soft' : 'muted';
};
export const cellTones = (s) => {
  const t = {};
  if (s.i < 0) return { 0: 'strong' };
  for (let k = 0; k <= s.i; k++) t[k] = 'done';
  t[s.eligible] = s.wrong ? 'warn' : 'accent';
  t[s.i + 1] = s.wrong ? 'warn' : 'strong';
  return t;
};
export const pointersFor = (s) => {

    { at: s.eligible, label: '接上', side: 'bottom', tone: s.wrong ? 'warn' : undefined },
    { at: s.i, label: '跳过', side: 'bottom' },
  ];
};

## 题目

一个浏览器同一时刻只能跑一个任务。从一组时间段固定的任务里挑一些互不重叠的，求最大总收益。

- 输入：任务 `[start, end, value]` 占用半开区间 [start, end)，做完得 value。每个任务最多做一次，也可以都不做。
- 首尾相接不算冲突：3 结束的任务和 3 开始的任务可以都选。
- start、end 是整数，`start < end`；value 是正整数。不满足时抛出异常。
- 任务列表可以为空，此时返回 0。任务数至多 10 万。

## 样例

输入 `jobs = [[0,3,8], [1,2,3], [2,5,6], [3,5,7], [5,6,2]]`，输出 `17`。为了方便称呼，按输入顺序把它们叫作 A、B、C、D、E。

| 输入 | 输出 | 说明 |

第一个样例专门卡贪心。求“最多完成几个任务”时，先选结束最早的是对的。这里收益各不相同，先抢 B 只赚 3，却挤掉了能赚 8 的 A。第二个样例卡的是把首尾相接当成冲突。

## 思路

任务按结束时间排序，每个任务在“跳过”和“接下”之间取大；接下时用二分找出前面不冲突的任务。

先按结束时间排好：B(2)、A(3)、C(5)、D(5)、E(6)。C 和 D 都在 5 结束，排序稳定，保持输入顺序。

`best[i]` 表示只看排好序的前 i 个任务时的最大收益。轮到第 i 个任务（下标从 0 开始），只有两种选择：

- 跳过它：收益是 `best[i]`。
- 接下它：前面只能再选结束时间 ≤ start 的任务。任务已按结束时间排好，这些任务正好是一段前缀。设前缀长度是 `eligible`，收益是 `best[eligible] + value`。

`best[i + 1]` 取两者较大值。`eligible` 用二分求：在结束时间数组 `ends` 的前 i 项里数“≤ start 的有几个”，就是 Python `bisect_right` 返回的位置。

`best[eligible]` 是“前 eligible 个任务里的最优选法”，不是“上一个选中的任务”。处理 D 时，B 和 A 冲突，只能二选一，`best[2] = 8` 已经选好了 A。如果只记上一个选中的任务再往后接，B→C 和 A→D 两条路线容易混在一起。

为什么对？最优安排里要么没有第 i 个任务，值就是 `best[i]`；要么有，其余任务都在 start 之前结束，全在前 `eligible` 个里，最多贡献 `best[eligible]`。两种情况都算到了。

## 代码

<Solution slug="weighted-interval-scheduling" />

Python 直接用标准库的 `bisect_right(ends, start, 0, i)`，后两个参数把查找范围限制在前 i 项。TypeScript 没有对应的标准库函数，`solution.ts` 里自己写了一个 `bisectRight`：在 `[lo, hi)` 里找第一个大于 x 的位置，判断条件是 `arr[mid] <= x` 时往右走。把 `<=` 写成 `<` 就变成了 `bisect_left`，正是下面“自测”里的错误。

两种语言的排序都是稳定的（Python 的 `sorted`、ES2019 起的 `Array.prototype.sort`），结束时间相同的任务保持输入顺序。这个顺序不影响答案，只影响中间的 `best` 数组。TypeScript 的数字排序要写比较函数 `(a, b) => a[1] - b[1]`，否则会按字符串比较，10 会排在 9 前面。

## 复杂度

n 是任务个数。

- **时间 O(n log n)**：排序 O(n log n)；之后每个任务做一次二分，O(log n)。
- **空间 O(n)**：排好序的任务、`ends` 和 `best` 各占 O(n)。

## 自测：首尾相接的任务

<Aside type="caution" title="先在纸上算，再跑代码">
样例的正确答案是 17。如果你得到 10，多半是用了 `bisect_left`（或者手写二分时用了 `<`）：A 在 3 结束、D 在 3 开始，被误判成冲突。

如果你得到 11，是按结束时间贪心地选了 B、C、E，没有比较收益。

`[[0,2,4], [2,3,5], [3,5,1]]` 的正确答案是 10，三个任务首尾相接，全都能选。如果你得到 5，同样是把相接当成了冲突：[2,3) 和两边都“撞上”，最多只能凑出 5。
</Aside>

## 延伸：最多只接 k 个任务呢？

比如浏览器每天最多开 k 次会话。“跳过 / 接下”照旧，只是接下要用掉一个名额，状态多一维：`best[i][c]` 表示只看前 i 个任务、最多接 c 个时的最大收益。

转移变成 `best[i+1][c] = max(best[i][c], best[eligible][c-1] + value)`。`eligible` 的求法不变，二分只和时间有关。

样例里 k = 1 时只能挑一个最值钱的，答案 8（A）；k = 2 时是 A + D = 15；k = 3 时回到原题的 17，再大也不会变。时间变成 O(n log n + n·k)，空间 O(n·k)。
