## 题目

一个 Agent 在单线程里调用工具，工具之间可以嵌套：A 运行时调用 B，B 结束之前 A 暂停。日志 `events` 的每一项是 `(t, tool, kind)`：

- `t` 是整数时刻（秒），表示事件发生的那一瞬间；
- `tool` 是工具名；
- `kind` 是 `"start"` 或 `"end"`。

日志按发生顺序给出，同一时刻可以有多条事件。一次调用占用 `[start, end)` 这段时间，开始和结束在同一时刻时耗时为 0。工具可以直接或间接地调用自己。

返回一个字典，键是日志里出现过的每个工具，值是它的**独占耗时**：它自己干活的时间，子调用期间不算。没有任何工具在运行的空闲时间不记给谁。空日志返回空字典。

以下情况是非法日志，抛出 `ValueError`（TypeScript 抛 `Error`）：

- 时间戳倒退；
- `end` 的工具不是最近一个还没结束的调用；
- 日志结束时还有调用没结束；
- `kind` 不是这两个值之一。

## 样例

样例 1：

```text
events = [(0, "A", "start"), (2, "B", "start"),
          (4, "B", "end"), (5, "A", "end")]
输出   = {"A": 3, "B": 2}
```

样例 2：

```text
events = [(0, "agent", "start"), (1, "search", "start"),
          (3, "search", "end"), (3, "agent", "start"),
          (5, "agent", "end"), (6, "agent", "end"),
          (8, "search", "start"), (9, "search", "end")]
输出   = {"agent": 4, "search": 3}
```

样例 1：A 从 0 到 5 共 5 秒，但 2 到 4 在等 B，自己只干了开头 2 秒和最后 1 秒。

样例 2 有三处容易错：`agent` 调用了自己，两层的时间不能重复计；时刻 3 上 `search` 结束和内层 `agent` 开始同时发生；6 到 8 没有工具在跑。

## 思路

用栈存还没结束的调用，栈顶就是此刻在干活的工具。每读一条日志，先把距上一条日志的时间记给栈顶，再入栈或出栈。

图里外层 `agent` 的条最长，但 1 到 5 这 4 秒它都在等别人。任一时刻真正干活的只有一个工具：嵌套最深、还没结束的那个。调用后开始的先结束，所以按开始顺序放进栈，它就在**栈顶**。

相邻两条日志之间栈不会变，这段时间都属于同一个栈顶。读到一条新日志时分两步：

1. 结算：`t - previous` 秒记给旧的栈顶。栈空就跳过，这段是空闲。
2. 处理事件：`start` 入栈，`end` 出栈。

顺序不能反。读到 `(3, search, end)` 时，1 到 3 这 2 秒是 `search` 干的；先出栈再结算，这 2 秒就记到 `agent` 头上了。

相邻日志把时间轴切成一段段，每段在读到它右端那条日志时结算一次，记给当时唯一在干活的工具，或者算空闲。没有哪一秒记两次或漏掉：样例 2 里 4 + 3 + 空闲 2 = 9，正好是整条时间轴。

递归也不用特殊处理。栈里有两个 `agent` 时，每段时间只记给栈顶那个，再按名字累加。另一种常见写法是在 `end` 时算 `end - start`，再从父调用里扣掉子调用的时长。这也能做对，前提是开始时间跟着栈走。如果用“工具名 → 开始时间”的字典，内层 `agent` 在时刻 3 开始时会覆盖外层记下的 0，外层就算错了。

## 代码

Python 返回 `dict`，TypeScript 返回 `Map<string, number>`。两者都按工具第一次出现的顺序排列键。用 `Map` 而不是普通对象，是因为工具名是任意字符串：如果有个工具叫 `constructor` 或 `__proto__`，写进 `{}` 会碰到原型链上的同名属性。

`elapsed.setdefault(tool, 0)` 这一行让“开始即结束”的工具也出现在结果里，值为 0。去掉它，`(4, ping, start)` `(4, ping, end)` 会返回空字典。

## 复杂度

n 是日志条数，d 是最大嵌套深度，m 是不同工具的个数。

- **时间 O(n)**：每条日志只做一次加法和一次入栈或出栈。
- **空间 O(d + m)**：栈里最多同时有 d 个调用，结果字典有 m 项。

## 自测：递归和空闲

<Aside type="caution" title="先在纸上算，再跑代码">
`(0, A, start)` `(2, A, start)` `(5, A, end)` `(7, A, end)` 的正确答案是 `{A: 7}`。如果你得到 10，说明每次调用都按 `end - start` 累加，没有扣掉子调用，内层的 3 秒算了两次。如果得到 5，说明开始时间按工具名存进了字典，内层在时刻 2 开始时覆盖了外层记下的 0。

`(0, A, start)` `(1, A, end)` `(4, B, start)` `(6, B, end)` 的正确答案是 `{A: 1, B: 2}`。如果 A 得到 4，说明你把 1 到 4 的空闲记给了“最近一个出现的工具”，没有先检查栈是不是空的。
</Aside>

## 延伸：结束时刻也算在内呢？

力扣 636 用的是另一种约定：时间按整格算，`end 4` 表示“第 4 格也跑完了”，所以一次调用占 `[start, end + 1)`。样例 1 换成这个约定，B 占 2、3、4 三格，A 占 0、1、5 三格，答案变成 `{A: 3, B: 3}`。

栈的做法完全不变，只改结算的边界：

- 读到 `start t`：结算到 `t`，和原来一样，因为第 t 格属于新开始的工具。
- 读到 `end t`：结算到 `t + 1`，并把 `previous` 设成 `t + 1`。下一条日志从第 t + 1 格开始算。

<Solution slug="exclusive-tool-time" file="followup" />

开始和结束在同一格时，原题耗时为 0，这个约定下是 1。力扣 636 的样例 1，日志 `(0, 0, start)` `(2, 1, start)` `(5, 1, end)` `(6, 0, end)`，用这段代码算出 `{0: 3, 1: 4}`，和官方答案 `[3, 4]` 一致。
