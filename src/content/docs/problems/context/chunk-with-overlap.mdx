## 题目

一篇文档已经切成了 n 个 token，编号 0 到 n − 1。把它切成若干块，每块最多 `size` 个 token，相邻两块重叠 `overlap` 个 token：

- 第一块从 0 开始，每一块的起点比上一块多 `size − overlap`。
- 每块到 `起点 + size` 为止，超出文档就截到 n，所以最后一块可以不足 `size` 个。
- 某一块已经包含最后一个 token（终点等于 n）时就停，不再往后切。

返回所有块的半开区间 `(start, end)`，表示 token `start` 到 `end − 1`。

`n = 0` 时返回空列表。参数必须满足 `n ≥ 0`、`size ≥ 1`、`0 ≤ overlap < size`，否则抛出错误。

## 样例

| n | size | overlap | 输出 |
|---|---|---|---|
| 10 | 4 | 1 | `[(0, 4), (3, 7), (6, 10)]` |
| 7 | 4 | 1 | `[(0, 4), (3, 7)]` |
| 0 | 4 | 1 | `[]` |

前两个样例针对同一个错误：用 `range(0, n, size - overlap)` 枚举起点。n = 10 时起点是 0、3、6、9，多出 `(9, 10)`；n = 7 时起点是 0、3、6，多出 `(6, 7)`。多出的块里的 token，前一块都有。

## 思路

起点每次前进 `size − overlap`，终点取 `min(start + size, n)`，切出的块到达末尾就停。

**步长**是相邻两块起点的距离。一块有 `size` 个 token，最后 `overlap` 个留给下一块当开头，所以下一块往前走 `size − overlap`。这里是 4 − 1 = 3。

每块的终点是 `min(start + size, n)`。起点 6 的块终点是 min(10, 10) = 10，正好到末尾。

### 什么时候停

算完一块就检查 `end == n`，成立就停。

只看起点会出错。如果用 `start < n` 判断，n = 7 时起点 6 也满足 6 < 7，于是多切一块 `[6, 7)`：

`[6, 7)` 的内容块 2 里全有。检索时它会和块 2 一起被召回，白占一个名额。

代码里的 `while start < n` 只用来处理 `n = 0`：空文档一块都不切。

### 参数为什么要检查

`overlap ≥ size` 时步长 ≤ 0。`overlap = size = 4` 时步长是 0，起点一直是 0，循环不会结束；`overlap` 更大时起点还会往回退。`size = 0` 时每块都是空的，同样停不下来。所以先检查参数，不满足直接报错。

### 为什么要重叠

一句话可能正好跨在两块的边界上。比如“退票须在开车前 30 分钟办理”，前半句在第一块末尾，后半句在第二块开头，两块单独看都说不清。

有了重叠，边界附近的 `overlap` 个 token 会同时出现在两块里。一句话只要不比 `overlap` 长，就一定完整地落在某一块里。代价是这部分内容存了两遍，块数也变多。

两个版本结构相同。Python 返回元组列表，TypeScript 返回 `[start, end]` 数组的数组。参数检查在 Python 里写成连比 `0 <= overlap < size`。同样的写法在 JavaScript 里也能运行，意思却不同：先算出 `0 <= overlap` 的布尔值，再拿 `true`/`false` 和 `size` 比。所以 TypeScript 版拆成 `overlap < 0 || overlap >= size` 两个条件。

## 复杂度

n 是 token 数，s 是 `size`，o 是 `overlap`。

- **时间 O(n / (s − o) + 1)**：块数 m 满足 m = 1 + ⌈(n − s) / (s − o)⌉（n > s 时；n ≤ s 时只有 1 块），每块只算一次 `min`。例如 n = 1000、s = 128、o = 32 时步长 96，块数 1 + ⌈872 / 96⌉ = 11。
- **空间 O(m)**：只存输出的 m 个区间，不复制 token 本身。

## 延伸：希望每块都不在句子中间断开呢？

固定长度切块不管句子边界。改成按整句装：先按句号等标点把文档切成句子，第 i 句有 `lengths[i]` 个 token，块的单位从 token 变成句子。

句子长短不一，步长不再固定。要改三处：

1. 装句子：从当前句开始往块里放整句，放下一句会超过 `size` 就收尾。如果某一句本身就超过 `size`，它单独成块（实际使用时再对这一句用本题的固定长度切法）。
2. 重叠：下一块的开头带上这一块末尾的几句，带上的总 token 数不超过 `overlap`。带上之后还要装得下下一句新内容，装不下就少带一句。也不能把整块都带过去，否则不会往前走。
3. 停止条件不变：这一块已经装到最后一句就停。

<Solution slug="chunk-with-overlap" file="followup" />

拿 5 句话试，每句的 token 数是 `[3, 2, 4, 1, 3]`，`size = 6`，`overlap = 2`：

- 第一块从第 0 句开始：3 + 2 = 5，再加第 2 句的 4 就超了，块是第 0–1 句，句子区间 `(0, 2)`。
- 往回带：第 1 句有 2 个 token，不超过 2；带上之后 2 + 4 = 6 也装得下第 2 句。第二块从第 1 句开始：2 + 4 = 6，再加 1 就超了，块是 `(1, 3)`。
- 往回带：第 2 句有 4 个 token，超过 2，不带。第三块从第 3 句开始：1 + 3 = 4，到最后一句了，块是 `(3, 5)`，停。

结果是 `[(0, 2), (1, 3), (3, 5)]`。换算成 token 区间是 `[0, 5)`、`[3, 9)`、`[9, 13)`：第一、二块重叠 2 个 token；第二、三块没有重叠，因为第 2 句有 4 个 token，比 `overlap` 长。按整句切，重叠量不再固定，只保证不超过 `overlap`。
