## 题目

给一个查询向量 `q` 和一组文档向量 `docs`，找出和查询方向最接近的 `k` 篇文档，返回它们在 `docs` 里的下标，按相似度从高到低排。

- 相似度用余弦：cos = (q · v) / (|q| · |v|)，范围是 −1 到 1。
- 逐篇比较，不做近似检索。
- 相似度在数学上相等时，下标小的在前。
- 所有向量维数相同，分量是绝对值不超过 1000 的整数，维数不超过 1024。
- 全零的文档向量没有方向，跳过，不参与排名。
- `k <= 0` 返回空列表；`k` 超过非零文档数时，全部非零文档排好返回。
- 查询向量全为零，或者某个文档的维数和查询不同，抛出 `ValueError`（TypeScript 版抛出 `Error`）。

## 样例

| `q` | `docs` | `k` | 输出 |
|---|---|---|---|
| `[1,0]` | `[[1,1],[5,0],[0,0],[-1,0]]` | `3` | `[1,0,3]` |
| `[1,0]` | `[[3,4],[1,0]]` | `1` | `[1]` |
| `[1,0]` | `[[1,1],[3,3]]` | `2` | `[0,1]` |

第一个样例里，四篇文档的相似度依次约是 0.707、1、无定义、−1。下标 2 是零向量，跳过。下标 3 和查询反向，相似度 −1，仍然排进前 3。

第二个样例检查“只比点积”的写法：`[3,4]` 的点积 3 比 `[1,0]` 的 1 大，但 `[1,0]` 和查询同向。

第三个样例检查浮点并列：`[1,1]` 和 `[3,3]` 方向相同，相似度都是 1/√2，应该按下标排。

## 思路

逐篇打分，跳过零向量，按“分数降序、下标升序”排序取前 k 个。分数不用浮点余弦，而用整数分数 dot × |dot| / |v|²，这样并列能精确判断。

余弦只看夹角，不看长度。点积同时受夹角和长度影响：`[3,4]` 比 `[1,0]` 夹角大，但它长 5，点积反而更大。除以两边的长度就消掉了长度：3 / (1 × 5) = 0.6，1 / (1 × 1) = 1。

直接用浮点余弦排序会出错。第三个样例里，`[1,1]` 的浮点相似度是 0.7071067811865475，`[3,3]` 是 0.7071067811865476。数学上相等，浮点却差了最后一位，`[3,3]` 排到了前面，同分按下标的规则失效。

所以要把余弦换成**整数也能比较的分数**，分三步：

1. 所有文档除的都是同一个 |q|，去掉它不影响次序，只需比较 dot / |v|。
2. dot / |v| 里有开方。平方能去掉根号，但会丢掉正负号，所以改乘 dot × |dot|，得到 dot × |dot| / |v|²。x 越大，x × |x| 也越大，次序不变。
3. dot 和 |v|² 都是整数，这个分数能用 `Fraction` 精确表示，也能交叉相乘比较。

样例 1 的排序分数是 1/2、1、跳过、−1，从高到低是下标 1、0、3，和余弦的次序一致。

负分不能扔。如果把“目前最好的分数”初始化成 0，只保留比 0 大的文档，遇到只剩反向向量的库就会出错。例如 `q = [1,0]`、`docs = [[-1,0],[0,0]]`、`k = 1`，正确答案是 `[0]`，这种写法返回空列表。

## 代码

<Solution slug="cosine-top-k" />

Python 用 `Fraction(dot * abs(dot), sq)` 作排序键。Python 整数没有上限，比较一定精确。

TypeScript 要注意数的大小。分量不超过 1000、维数不超过 1024 时，点积和 |v|² 都不超过约 10⁹，用 `number` 算是精确的。但 dot × |dot| 能到 10¹⁸，交叉相乘再乘一个 |v|²，能到 10²⁷，都超过了 `Number.MAX_SAFE_INTEGER`（约 9 × 10¹⁵）。所以先把 dot 转成 `bigint` 再相乘，比较也在 `bigint` 上做。`bigint` 不能和 `number` 混用，比较函数最后要返回 −1、0、1 这样的 `number`。

## 复杂度

n 是文档数，d 是维数。

- **时间 O(n·d + n log n)**：每篇文档算一次点积和长度平方，各 d 次乘加；排序 n log n 次比较。每次比较是几个大整数相乘，位数有上限（约 90 位二进制），看作常数。
- **空间 O(n)**：保存每篇文档的分数。

k 远小于 n 时，可以用大小为 k 的堆代替全排序，排序部分降到 O(n log k)，但每篇文档的打分 O(n·d) 省不掉。

## 延伸：文档库不变、查询很多时，哪部分可以提前算？

文档的长度 |v| 不随查询变化。入库时就把每篇非零文档除以自己的长度，变成单位向量。查询来了也先除以自己的长度。两个单位向量的点积就是余弦，不用再除。

两个单位向量的欧氏距离平方等于 2 − 2 × 点积。例如 `q = [1,0]` 和 `[1,1]` 归一化后的 `[0.7071, 0.7071]`，点积 0.7071，距离平方 (1 − 0.7071)² + 0.7071² ≈ 0.586，正好是 2 − 2 × 0.7071。点积越大，距离越小，所以“余弦最大”和“欧氏距离最近”排出的次序相同。只支持欧氏距离的向量索引，也能用来做余弦检索。

<Solution slug="cosine-top-k" file="followup" />

代价是又回到了浮点。归一化后，`[1,1]` 和 `[3,3]` 的单位向量差在最后一位，查询 `[1,0]` 时 `CosineIndex` 返回 `[1,0]`，精确版返回 `[0,1]`。并列必须严格按下标排时，只能用上面的整数比较。不在乎这种并列时，预先归一化能让每次查询省掉 n 次开方和除法。测试里用 60 篇随机文档、30 次查询，对比了归一化版本、精确版本和按距离排序三者的结果，没有并列时完全一致。
