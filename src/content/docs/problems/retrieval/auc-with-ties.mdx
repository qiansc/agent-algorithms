## 题目

二分类模型给 n 个样本各打了一个分数 `scores[i]`（实数，越大越像正样本），真实标签是 `labels[i]`（1 是正样本，0 是负样本）。返回 AUC。

- 一个正样本和一个负样本组成一个“正负对”。AUC 是所有正负对中，正样本分数更高的比例。
- 两个分数相等时，这一对记 0.5。“相等”指数值完全相等，不做四舍五入。
- 两个列表长度不同、标签不是 0 或 1、分数里有 NaN，抛出错误（Python 抛 `ValueError`，TypeScript 抛异常）。
- 没有正样本或没有负样本时，也抛出错误。
- 要求 O(n log n)。P、N 分别是正、负样本个数，逐对比较的 O(P·N) 写法只能用来核对答案。

## 样例

| 样本 | A | B | C | D | E | F |
|---|---|---|---|---|---|---|
| `scores` | 0.9 | 0.8 | 0.8 | 0.6 | 0.3 | 0.3 |
| `labels` | 1 | 1 | 0 | 0 | 1 | 0 |

输出：`0.6666…`（等于 6/9）。

样例里有两组并列，每组都是一正一负：B 和 C 都是 0.8，E 和 F 都是 0.3。几种常见写法的结果：

| 写法 | 结果 |
|---|---|
| 正确：并列记 0.5 | 6/9 ≈ 0.667 |
| 并列记 0 | 5/9 ≈ 0.556 |
| 并列记 1 | 7/9 ≈ 0.778 |
| 排序后直接用位置当名次，不取平均 | 5/9 ≈ 0.556（这份输入恰好和“记 0”一样） |

## 思路

按分数从低到高排序，同分的样本记平均名次，再用 Mann–Whitney 公式 U = 正样本名次和 − P(P + 1) / 2 算出正样本赢的对数，AUC = U / (P · N)。

### 不逐对比较，改用名次

逐对比较要 P × N 次，正负样本各 10 万个时就是 100 亿次。

把所有样本按分数从低到高排好，名次就是位置（最低的是 1）。一个正样本的名次减 1，是排在它下面的样本数。其中负样本的个数就是这个正样本赢的对数，正样本要扣掉。

P 个正样本两两之间，每一对里总有一个排在另一个下面，所以要扣掉的正样本一共 P(P − 1) / 2 个。把每个正样本的“名次 − 1”加起来，再扣掉这部分：

U = 正样本名次和 − P − P(P − 1) / 2 = 正样本名次和 − P(P + 1) / 2

U 就是正样本赢的对数，AUC = U / (P · N)。这个 U 在统计里叫 Mann–Whitney U 统计量。

**有并列时，名次要取平均。** 0.8 那一组占位置 4 和 5，B 和 C 都记 4.5。B 记 4.5 而不是 4 或 5，相当于下面的 C 只算半个，对应并列记 0.5。两个正样本并列时，各记平均名次，互相各算半个，加起来还是 1，扣掉的 P(P − 1) / 2 不受影响。

最后一帧说明并列一定要取平均。不取平均时，并列组里谁在前取决于排序怎么摆放同分样本。这份输入用稳定排序，B 在 C 前、E 在 F 前，两个正样本都占了较小的位置，结果和“并列记 0”一样。如果输入里 C 写在 B 前面，答案又会变。同一份数据换个顺序 AUC 就变，这不对。

<Solution slug="auc-with-ties" />

排序排的是下标 `order`，不改原数组。外层 `while` 每次找出一段同分的样本 `order[i:j]`，它们占名次 i + 1 到 j，平均名次是 (i + 1 + j) / 2，乘上这一段里正样本的个数后累加。

两种语言的差异：

- JavaScript 的 `sort` 不传比较函数时按字符串比较，这里写了 `(a, b) => scores[a] - scores[b]`。
- NaN 和任何数比较都不成立，排序会乱，所以两边都先检查。Python 用 `s != s` 判断 NaN，TypeScript 用 `Number.isNaN`。
- 平均名次只可能是整数或 .5，名次和在 2⁵³ 以内都能用双精度浮点精确表示，最后一步除法才产生舍入，两边结果一致。

## 复杂度

n 是样本数，P、N 是正、负样本数（P + N = n）。

- **时间 O(n log n)**：排序 O(n log n)。之后每个样本只在一个并列组里被访问一次，O(n)。逐对比较的写法是 O(P · N)，最坏是 O(n²)。
- **空间 O(n)**：下标数组 `order`。

## 自测：两个容易写错的输入

<Aside type="caution" title="先在纸上算，再跑代码">
`scores = [0.5, 0.5, 0.5, 0.5]`，`labels = [1, 0, 1, 0]`，正确答案是 0.5：四个正负对全部并列。如果你得到 0 或 1，并列被当成了输或赢；得到 0.25 或 0.75 之类的值，多半是用位置代替了平均名次。

`scores = [0.8, 0.8, 0.5, 0.2]`，`labels = [1, 1, 0, 0]`，正确答案是 1.0。并列只在两个正样本之间，不影响任何正负对。结果不是 1.0，说明扣除的部分写错了，应该是 P(P + 1) / 2 = 3。
</Aside>

本页代码还对完全分开、完全反过来、只有一正一负、一正一负同分、整数分数，以及 200 个只保留一位小数的随机样本跑过测试，并和 O(P · N) 的逐对比较对拍了 500 组随机输入。没有正样本、没有负样本、空输入、长度不一致、标签不是 0/1 都会报错。

## 延伸：按用户分组算 AUC 再平均（GAUC）呢？

把所有用户的样本混在一起算 AUC，会拿 A 用户的负样本和 B 用户的正样本比高低。但很多时候模型只需要在同一个用户的候选之间排好序，跨用户谁高谁低不影响给每个人看什么。GAUC 这样算：

1. 按用户分组，每组单独算 AUC。
2. 只有一种标签的用户（全是正或全是负）算不出 AUC，跳过。
3. 剩下的用户按各自的样本数加权平均。

单组的 AUC 用本题的函数，并列照样记 0.5，只是外面加了一层分组和加权。

<Solution slug="auc-with-ties" file="followup" />

拿 9 个样本试：

| 用户 | 分数 | 标签 | 本组 AUC |
|---|---|---|---|
| u1 | 0.9, 0.8, 0.8 | 1, 1, 0 | (1 + 0.5) / 2 = 0.75 |
| u2 | 0.4, 0.3, 0.2, 0.1 | 1, 1, 0, 0 | 1 |
| u3 | 0.95, 0.05 | 0, 0 | 只有负样本，跳过 |

GAUC = (3 × 0.75 + 4 × 1) / (3 + 4) = 6.25 / 7 = 25/28 ≈ 0.893。

9 个样本不分用户放在一起算，AUC 只有 27/40 = 0.675。差距来自跨用户的比较：u1 的负样本 0.8 比 u2 的两个正样本都高，u3 的负样本 0.95 比所有正样本都高。这些对在用户内部都不存在，GAUC 不算它们。
