## 题目

原文是切好词的列表 `tokens`，查询词列表是 `wanted`，可能有重复。找出 `tokens` 里最短的连续区间，使 `wanted` 里每个词在区间内出现的次数**不少于**它在 `wanted` 里的次数。例如 `wanted` 有两个 `A`，区间里至少要有两个 `A`。

- 用半开区间 `(left, right)` 表示 `tokens[left:right]`，包含 `left`，不包含 `right`。
- 最短的区间有多个时，返回 `left` 最小的那个。
- 找不到时返回 `None`（TypeScript 版返回 `null`）。
- `wanted` 为空时返回 `(0, 0)`。
- 词按字符串整体比较，区分大小写。

## 样例

| `tokens` | `wanted` | 输出 |
|---|---|---|
| `["A","X","B","A","C","A","B"]` | `["A","A","B"]` | `(0, 4)` |
| `["A","X","B","A","C","A","B"]` | `["A","B"]` | `(2, 4)` |
| `["A","X","B","A","C","A","B"]` | `[]` | `(0, 0)` |
| `["A","X","B","A","C","A","B"]` | `["A","A","A","A"]` | `None` |

第一个样例里，[0, 4)、[2, 6)、[3, 7) 三段都有两个 `A` 和一个 `B`，长度都是 4，取最靠左的 [0, 4)。它检查两件事：`A` 要数够两份；长度并列时不能被后面的窗口覆盖。第二个样例只要一个 `A`，最短的是 `B A` 这一段 [2, 4)。

## 思路

用滑动窗口：右端每往右挪一格，就把左端尽量往右收，直到再收就不合法。用一本“还欠几份”的账判断窗口是否合法。

暴力枚举有 O(n²) 个区间，每个检查 O(n)。滑动窗口的左右两端都只往右走，总共 O(n) 步。

账本有两项：

- `need[w]`：词 w 还欠几份。开始时就是 `wanted` 里的计数，样例 1 是 A 欠 2、B 欠 1。
- `remaining`：一共还欠几份，开始是 3。它等于 0 时，窗口合法。

右端读入查询词 w 时，`need[w]` 减 1。只有减之前 `need[w] > 0`，这一份才是真欠着的，`remaining` 才减 1。左端移出 w 时反过来：`need[w]` 加 1，加完大于 0 说明移走的是必需的一份，`remaining` 加 1。

收左端不会错过答案。窗口 [left, right) 合法时，以 `left` 开头的合法区间里它已经最短，右端再往右只会更长。记下它以后，`left` 这个起点就可以丢掉。

`need[w]` 可以是负数，表示窗口里这个词多出几份。例如 `tokens = ["A","A","A","B","A"]`、`wanted = ["A","B"]`：读完前三个 `A`，A 的账是 1 − 3 = −2。读入 `B` 后窗口合法，开始收左端。移出第一个 `A`，账变成 −1；移出第二个，账变成 0，都不欠；移出第三个，账变成 1，才又欠上。答案是 `(2, 4)`。如果把负数截成 0，第一次移出就会误以为欠上了。

## 代码

<Solution slug="shortest-evidence-window" />

Python 用 `Counter` 做账本，TypeScript 用 `Map`。两者都只为查询词建账，不在 `wanted` 里的词直接跳过。判断用 `word in need` 和 `need.has(word)`，不要看 `need[word]` 的真假，因为账是 0 时它照样是查询词。

Python 版的 `right` 从 1 开始数，直接就是半开区间的右端；TypeScript 版用 `right - 1` 取当前词，含义相同。返回值 Python 是元组，TypeScript 是长度为 2 的数组 `[left, right]`。

## 复杂度

n 是原文的词数，m 是查询词的个数（含重复），u 是查询里不同词的个数。

- **时间 O(n + m)**：建账本 O(m)。`right` 从头走到尾，`left` 也最多走 n 步，每一步只做常数次字典操作。
- **空间 O(u)**：账本里只有查询词。

## 延伸：查询词必须按顺序出现呢？

改一个条件：`wanted` 里的词必须在窗口中按给定顺序出现，中间可以夹别的词，也就是 `wanted` 是窗口的子序列。

账本只记每个词还欠几份，不管先后，不再够用。样例 1 的 [0, 4) 是 `A X B A`，出现顺序是 A、B、A，不是 A、A、B，不合法。

改成按顺序匹配。`start[j]` 记录：读到目前为止，按顺序匹配完 `wanted[0..j]` 时，第一个词最晚能从哪里开始。读入第 r 个词时，j 从大到小检查：

- 词等于 `wanted[0]` 时，`start[0] = r`。
- 词等于 `wanted[j]` 且 `start[j − 1]` 已有值时，`start[j] = start[j − 1]`。

j 从大到小，同一个词就不会在这一步既当 `wanted[j − 1]` 又当 `wanted[j]`。每当词等于最后一个查询词，`(start[m − 1], r + 1)` 就是以 r 结尾的最短候选。

在样例 1 上走到最后一个 `B`（下标 6）：`start[0]` 是最近的 `A`，下标 5；`start[1]` 是“A、A”最晚的起点，下标 3（用了下标 3 和 5 两个 `A`）；于是 `start[2] = 3`，答案是 (3, 7)。(0, 4) 和 (2, 6) 都不满足顺序。

时间变成 O(n·m)：每读一个词都要把 m 个查询位置扫一遍，空间 O(m)。这个做法在 500 组随机输入上和暴力枚举对比过。
