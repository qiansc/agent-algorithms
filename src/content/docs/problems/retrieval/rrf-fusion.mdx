export const listTones = (cur, li) => {
  if (cur === -2) return li === 0 ? { 2: 'warn' } : {};
  if (cur === -1) return lists[li].map(() => 'done');
  if (li < cur) return lists[li].map(() => 'done');
  if (li === cur) return lists[li].map(() => 'strong');
  return {};
};

## 题目

几路检索各给出一张文档榜单，只有名次，没有可比的分数。把它们合成一张榜。

- 输入 `ranks` 是若干张榜单，每张是一个整数编号列表，越靠前名次越高。同一张榜里编号不重复，不同榜之间可以重复。
- 文档在某张榜上排第 r 名（从 1 数起），从这张榜得 1/(c + r) 分；不在榜上得 0 分。总分是各榜得分之和。
- 返回总分最高的 `k` 个编号，按总分从高到低。总分在数学上相等时，编号小的在前。
- `c` 是正整数，默认 60。`k = 0` 返回空列表，`k` 超过文档总数时全部返回。
- `c` 不是正整数，或 `k` 是负数时，抛出 `ValueError`（TypeScript 版抛出 `Error`）。
- 每张榜最多 50 篇。

## 样例

| `ranks` | `k` | `c` | 输出 |
|---|---|---|---|
| `[[9,2,5],[2,5],[5,9]]` | `2` | `1` | `[5,2]` |
| `[[9,2,5],[2,5],[5,9]]` | `10` | `1` | `[5,2,9]` |
| `[[9,2],[2,5],[5,9]]` | `3` | `1` | `[2,5,9]` |

第一个样例里，5 在三张榜上都出现了，只是在榜一排最后，最终拿了第一名。第三个样例把同样的数据截成每榜前两名，5 丢了榜一的分，三篇文档同分。所以**不能自己先把每张榜截短再合并**。

## 思路

用一张字典给每篇文档累加 1/(c + r)，累加时用精确分数，最后按总分降序、编号升序取前 k 个。

这种方法叫倒数排名融合（Reciprocal Rank Fusion，RRF）。c = 1 时，第 1 名得 1/2，第 2 名得 1/3，第 3 名得 1/4。名次越靠前分越高，但差距越来越小。

它只用名次，不用各路自己的分数。向量检索给 0.83 这样的余弦相似度，关键词检索给 12.7 这样的 BM25 分，量纲不同，直接相加没有意义。名次在哪一路里都能比。

最后一帧说明所有名次都要算进去。5 在榜一只拿到 1/4，正是这 1/4 让它的 13/12 超过了 2 和 9 的 5/6。截掉它，第一名就换人了。

2 和 9 的总分都是 5/6，这时按编号排。这里的“相等”是数学上的相等。如果用浮点数累加，每次相加都有舍入误差，本该相等的两个总分可能差在最后一位，同分规则就失效了。所以 Python 版用 `fractions.Fraction` 精确累加。

## 代码

<Solution slug="rrf-fusion" />

两种语言的差别在精确分数上。Python 标准库有 `Fraction`，加法和比较都精确。JavaScript 没有分数类型，TypeScript 版用两个 `bigint` 存分子和分母：相加时通分，再用最大公约数约分；比大小时交叉相乘，比较 `a × d` 和 `c × b`。

不能直接用 `number`。例如 c = 60：文档 3 在榜一第 12 名、榜二第 28 名，总分 1/72 + 1/88；文档 8 在榜一第 6 名、榜二第 39 名，总分 1/66 + 1/99。两者都等于 5/198，应该按编号把 3 排在前面。浮点加法却算出 0.025252525252525252 和 0.025252525252525256，文档 8 多了一点，排到了前面。

分子分母要用 `bigint`，因为分母是若干个 c + r 的乘积再约分。榜单一多，它可能超过 `Number.MAX_SAFE_INTEGER`（约 9 × 10¹⁵），普通整数乘法会丢精度，交叉相乘就不可靠了。`bigint` 没有上限。

排序比较函数先比分数，相等时返回 0，`||` 接着比编号，对应 Python 排序键 `(-scores[doc], doc)`。

## 复杂度

L 是所有榜单的总条目数，u 是不同文档的个数。

- **时间**：累加做 L 次分数加法，排序做 O(u log u) 次分数比较。分数运算不是 O(1)，耗时随分子分母的位数增长；本题每榜不超过 50 篇，分母不会超过 c + 1 到 c + 50 这些数的最小公倍数，实际很快。改用浮点数可以让每次运算 O(1)，代价是上面说的并列失效。
- **空间 O(u)**：每个文档存一个总分。

## 延伸：调大 c 会怎样？

c 决定名次之间的分差。同一张榜上第 1 名和第 2 名的得分之比是 (c + 2)/(c + 1)：

- c = 1 时是 3/2，第 1 名比第 2 名多 50%。
- c = 60 时是 62/61，只多 1.6% 左右。

c 越大，同一张榜上的前后名次越接近，“在几张榜上出现”就越重要。看这个输入：`ranks = [[1,5,6,2],[3,7,8,2]]`，`k = 1`。

| | 文档 1（榜一第 1 名） | 文档 2（两张榜都是第 4 名） | 答案 |
|---|---|---|---|
| c = 1 | 1/2 = 0.5 | 1/5 + 1/5 = 0.4 | `[1]`（文档 3 也是 1/2，编号更大） |
| c = 60 | 1/61 ≈ 0.0164 | 1/64 + 1/64 ≈ 0.0313 | `[2]` |

c = 1 时，一个第 1 名胜过两个第 4 名；c = 60 时，两个第 4 名胜出。算法不用改，只是换个参数，测试里两种 c 都跑过。RRF 原论文用的就是 c = 60。

c 越大越看重“几路都认可”，某一路独家找到的好结果就更难冒头。另外，如果上游各路已经截成不同长度，短榜里的文档天然少拿分。
