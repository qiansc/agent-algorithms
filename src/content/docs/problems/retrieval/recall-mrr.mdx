## 题目

给定一批查询的检索结果和整数 `k`，算出 `(Recall@K, MRR@K)`。每个查询有两项输入：

- `ranking`：检索器返回的文档编号列表，越靠前名次越高。可能有重复编号，重复的也占一个位置。
- `relevant`：人工标注的相关文档编号集合。

每个查询只看 `ranking` 的前 `k` 个位置（不足 `k` 个就全看），算两个分数：

- 召回率：前 `k` 个里出现过的**不同**相关编号个数，除以 `relevant` 的大小。
- 倒数排名：第一个相关编号所在位置的倒数，位置从 1 数起；前 `k` 个里没有相关编号，记 0。

再按查询取平均：

- 返回两个分数各自的平均值 `(Recall@K, MRR@K)`。
- `relevant` 为空的查询不参与平均。
- 所有查询都被跳过，或者没有查询，返回 `(0.0, 0.0)`。
- `k` 可以为 0；为负数时抛出错误。

## 样例

`k = 3`，三个查询：

| 查询 | `ranking` | `relevant` |
|---|---|---|
| q1 | `[8, 2, 2, 7]` | `{2, 7}` |
| q2 | `[5, 3]` | `{5}` |
| q3 | `[4]` | `{}`（空） |

输出：`(0.75, 0.75)`。

这个样例有三处容易写错，各自会得到下面的结果：

| 写法 | 结果 | 错在哪里 |
|---|---|---|
| 正确 | `(0.75, 0.75)` | |
| 忘了截断到前 `k` 个 | `(1.0, 0.75)` | q1 第 4 位的 7 被算成命中 |
| 按位置数命中次数 | `(1.0, 0.75)` | q1 的两个 2 被算成 2 次命中，召回 2/2 |
| 空标注的查询也计入平均 | `(0.5, 0.5)` | 分母从 2 变成 3 |

## 思路

每个查询扫一遍前 `k` 个位置：命中的编号放进集合（去重），同时记下第一个命中的位置。跳过空标注的查询，最后对其余查询取平均。

拿 q1 来说，`k = 3`，只看 `[8, 2, 2]`：

- 第 1 位是 8，不在 `{2, 7}` 里。
- 第 2 位是 2，命中。这是第一个命中，倒数排名是 1/2 = 0.5。把 2 记进“已命中”集合。
- 第 3 位又是 2。它占一个位置，但集合里已经有 2，召回不变。
- 第 4 位的 7 在 `k` 之外，不看。

q1 找回了 2 和 7 中的 1 个，召回率 1/2 = 0.5；第一个相关结果排第 2，倒数排名 0.5。

召回率只管找没找到，相关文档排第 1 还是第 3 都一样。倒数排名只管第一个命中有多靠前：排第 1 得 1，排第 2 得 0.5，排第 3 得 0.33，之后的命中不再加分。

q2 只看 `[5, 3]`：第 1 位就命中唯一的相关编号 5，召回率 1/1 = 1，倒数排名 1/1 = 1。

q3 的 `relevant` 是空集，召回率的分母是 0，没法算分，所以跳过，不当作 0 分。

最后对参与的 q1、q2 取平均：召回率 (0.5 + 1) / 2 = 0.75，倒数排名 (0.5 + 1) / 2 = 0.75。倒数排名的平均就叫 MRR（mean reciprocal rank）。

换个顺序看两者的区别：q1 改成 `[2, 8, 7]`，召回率 2/2 = 1，倒数排名 1；改成 `[8, 2, 7]`，召回率还是 1，倒数排名降到 0.5。交换前两名只影响 MRR，不影响召回。

## 代码

<Solution slug="recall-mrr" />

`relevant` 先转成集合，传列表、元组或集合都可以，判断“在不在里面”平均 O(1)。命中的编号放进集合 `hits`，重复的只算一次。

Python 的 `ranking[:k]` 和 TypeScript 的 `ranking.slice(0, k)` 在 `k` 超过长度时只返回已有元素，不报错；`k = 0` 时返回空列表。两边都是浮点除法，结果相同。

## 复杂度

q 是查询个数，k 是截断位置，r 是所有查询的标注编号总数。

- **时间 O(q·k + r)**：每个查询最多看 k 个位置，每次判断平均 O(1)；把 `relevant` 转成集合要把所有标注编号过一遍。
- **空间 O(k + R)**：R 是单个查询最多的标注数。`hits` 最多 k 个编号，`relevant` 的集合副本最多 R 个，处理完一个查询就可以丢掉。

## 自测：两个容易写错的输入

<Aside type="caution" title="先在纸上算，再跑代码">
`[([9, 8, 7], {7})]`，`k = 2`，正确答案是 `(0.0, 0.0)`。7 在第 3 位，超出了前 2 个。如果你得到 `(1.0, 0.333…)`，说明没有截断到前 `k` 个。

`[([3], {3, 4})]`，`k = 10`，正确答案是 `(0.5, 1.0)`。结果只有 1 个，比 `k` 短，照常计算。如果程序报下标越界（TypeScript 里则是读到 `undefined`），说明循环写成了 `for i in range(k)` 再取 `ranking[i]`。
</Aside>

## 延伸：把命中数汇总再除以全体标注数，可以吗？

可以算，但回答的是另一个问题。本题是每个查询算一票：先算单个查询的召回，再平均，叫宏平均。汇总的做法是每条相关文档算一票：所有查询的命中数之和，除以所有查询的标注数之和，叫微平均。

各查询标注数差别很大时，两者差得很远。设 `k = 3`：

- 查询 A 有 100 篇相关文档（编号 1–100），返回 `[1, 500, 501]`，只找回 1 篇，召回 0.01。
- 查询 B 只有 1 篇相关文档 7，返回 `[7]`，找回了，召回 1。

宏平均是 (0.01 + 1) / 2 = 0.505；微平均是 (1 + 1) / (100 + 1) = 2/101 ≈ 0.0198。前者说“一半的查询做得不错”，后者说“绝大多数相关文档没找到”。

改成微平均，函数结构不变，只换累加的东西：分子累加命中数，分母累加标注数，最后除一次。空标注的查询给分子分母都加 0，不用特意跳过。

本页样例用微平均算是 2/3：q1 命中 1 篇、q2 命中 1 篇，共 3 篇标注。MRR 没有对应的微平均，因为它本来就是每个查询一个分数。
