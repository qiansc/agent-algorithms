## 题目

从 n 个候选片段里选出 k 个放进上下文。已知：

- `query_sim[i]`：片段 i 和查询的相似度。
- `pair_sim[i][j]`：片段 i 和片段 j 之间的相似度，矩阵对称。

用最大边际相关（Maximal Marginal Relevance，MMR）贪心地选：

- 第 1 轮选 `query_sim` 最大的片段。
- 之后每一轮，对每个还没选的片段 i 计算 `score = lam × query_sim[i] − (1 − lam) × 冗余`，选 `score` 最大的。“冗余”是片段 i 和**所有已选片段**相似度的最大值。
- 任何一轮出现同分，选下标小的。
- 返回选中的下标，按选中的先后排列。
- `k` 超过 n 时选完为止；`k <= 0` 或没有候选时返回空列表。
- `lam` 不在 0 到 1 之间，或 `pair_sim` 不是 n × n，抛出 `ValueError`（TypeScript 版抛出 `Error`）。

只按相关度取前 3 个，会得到 `[0, 1, 2]`，也就是 `lam = 1` 的结果。但片段 1 和片段 0 几乎一样，放进上下文等于浪费一个名额。`lam = 0.5` 时，片段 1 在第 2 轮和第 3 轮都没选上。第 3 轮还能暴露一个常见错误，见下面动画的最后一帧。

## 思路

按规则一轮轮贪心地选，用数组 `redundancy` 记住每个候选的冗余，每选中一个片段就更新一次，不必重新和所有已选片段比。

MMR 的“边际”指一个片段加进来能带来多少新信息。和查询越相关越好，和已选片段越像越差。`lam` 是两者的权重，`lam = 0.5` 表示一半看相关，一半看重复。

冗余取最大值，不取平均值。只要和某一个已选片段几乎相同，这个片段就是多余的。片段 1 和片段 2 只有 0.15，但和片段 0 有 0.95，冗余就是 0.95。

`redundancy[i]` 记的是片段 i 和已选片段的最大相似度。每选中一个新片段 `best`，只做一次 `redundancy[i] = max(redundancy[i], pair_sim[i][best])`。最大值可以一个个并进来，旧的已选片段不用再看。

第 3 轮片段 3 只得 0.00 也能选中，因为 MMR 不设门槛，每轮总要选出一个。片段 1 的 −0.05 比 0.00 小，输给了片段 3。

贪心每一轮只做当下最好的选择，不回头。它不保证选出的 3 个片段全局最优，但每一步都说得清理由。

两个版本一一对应。冗余的初始值是 `-math.inf` 和 `-Infinity`，表示“还没和任何已选片段比过”。第 1 轮只看相关度，用不到它。

同分选下标小的，靠 `score > best_score` 的严格大于：下标从小到大扫，后面的同分片段不会替换已记下的那个。

两种语言的浮点数都是 IEEE 754 双精度，式子和计算顺序相同，结果逐位相同。不过 0.5 × 0.85 − 0.5 × 0.95 实际算出来是 −0.04999999999999999，不是精确的 −0.05。由不同数字算出的两个得分，数学上相等，浮点结果也可能差在最后一位。题目的同分规则只对浮点下也完全相等的得分生效。

## 复杂度

n 是候选片段数，k 是要选的个数。

- **时间 O(n·k)**：最多 k 轮，每轮扫一遍 n 个候选算得分，再扫一遍更新冗余。朴素写法每个候选每轮要和最多 k 个已选片段比，是 O(n·k²)。
- **空间 O(n)**：`redundancy` 和 `picked` 两个数组，不算输入的 n × n 矩阵。

## 自测：两个容易写错的输入

<Aside type="caution" title="先在纸上算，再跑代码">
样例数据、`lam = 0.5`、`k = 3`，正确答案是 `[0, 2, 3]`。如果你得到 `[0, 2, 1]`，多半是冗余只和上一个选中的片段比了，忘掉了片段 1 和片段 0 的 0.95。把最大值写成平均值也会得到 `[0, 2, 1]`：片段 1 的冗余变成 (0.95 + 0.15)/2 = 0.55，得分 0.15，仍然高于片段 3 的 0.025。

`query_sim = [0.7, 0.7, 0.7]`、两两相似度都是 0.2、`lam = 0.5`、`k = 3`，正确答案是 `[0, 1, 2]`。如果第 1 轮选了片段 2，说明同分时没有取下标小的，比如比较时用了“大于等于”。
</Aside>

测试还覆盖了 `lam` 取 0、0.6、0.8、1，`k` 超过 n，`k = 0`，没有候选，只有一个候选，两种非法输入，以及 12 个随机候选。另外用 300 组随机数据，把增量维护冗余的写法和每轮重新比较的朴素写法逐一对比，结果完全一致。

## 延伸：lam 从 0 调到 1，结果怎么变？

数据不变，只改 `lam`。代码不用改，答案会经过三个阶段。

第 2 轮在片段 1 和片段 2 之间选：片段 1 的得分是 0.85·lam − 0.95·(1 − lam)，片段 2 是 0.5·lam − 0.1·(1 − lam)。两者相等时 lam = 17/24 ≈ 0.708。lam 比它大，第 2 轮就选片段 1。

lam 比 17/24 小时，第 2 轮选片段 2。第 3 轮在片段 1（冗余 0.95）和片段 3（冗余 0.30）之间选：令 0.85·lam − 0.95·(1 − lam) = 0.3·lam − 0.3·(1 − lam)，解得 lam = 13/24 ≈ 0.542。

| `lam` 的范围 | 例子 | 输出 |
|---|---|---|
| 0 ≤ lam < 13/24 | `lam = 0`、`0.5` | `[0, 2, 3]` |
| 13/24 < lam < 17/24 | `lam = 0.6` | `[0, 2, 1]` |
| 17/24 < lam ≤ 1 | `lam = 0.8`、`1` | `[0, 1, 2]` |

`lam = 0.6` 时，片段 1 第 2 轮输给片段 2，第 3 轮又回来了：它的得分 0.6 × 0.85 − 0.4 × 0.95 = 0.13，高于片段 3 的 0.6 × 0.3 − 0.4 × 0.3 = 0.06。

再看两个端点。`lam = 1` 时冗余项消失，就是纯按相关度排序。`lam = 0` 时第 1 个仍按相关度选，之后只看和已选片段有多不像，相关度不起作用。这个样例里它和 `lam = 0.5` 结果相同，换一组数据就可能选进和查询无关的片段。lam 越小，结果越分散。常见取值在 0.5 到 0.7 之间，要在自己的数据上试。

lam 正好是 13/24 或 17/24 时两个片段同分，按规则取下标小的。但这两个值在浮点下不能精确表示，实际结果取决于舍入，测试里避开了它们。
