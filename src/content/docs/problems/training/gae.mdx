## 题目

写 `gae(rewards, values, last_value, gamma, lam)`，返回一条 T 步轨迹每一步的 GAE 优势。

- `rewards[t]` 是第 t 步的奖励，`values[t]` 是价值网络对第 t 步状态的估值。
- `last_value` 是轨迹结束后那个状态的估值，走到终点时为 0。
- `gamma` 是折扣因子，`lam` 是平滑系数，都在 [0, 1] 内。

先算每一步的 TD 误差：

`δ_t = rewards[t] + gamma · V_{t+1} − values[t]`

其中 `V_{t+1}` 对前 T − 1 步是 `values[t+1]`，对最后一步是 `last_value`。再算 GAE 优势：

`A_t = δ_t + gamma · lam · A_{t+1}`

最后一步的 `A_{t+1}` 取 0。返回长度为 T 的列表 `[A_0, …, A_{T−1}]`。

- T = 0 时返回空列表。结果允许 1e-9 的误差。
- `rewards` 和 `values` 长度不同，或 `gamma`、`lam` 不在 [0, 1] 内，抛 `ValueError`（TypeScript 抛 `Error`）。

## 样例

三个样例都用 `rewards = [1, 0, 2]`、`values = [0.5, 0.4, 0.6]`、`last_value = 0`、`gamma = 0.9`，只改 `lam`：

| `lam` | 输出 | 说明 |
|---|---|---|
| 0.8 | `[1.68656, 1.148, 1.4]` | 正常情况 |
| 0 | `[0.86, 0.14, 1.4]` | 优势就是 TD 误差本身 |
| 1 | `[2.12, 1.4, 1.4]` | 优势是折扣回报减去估值 |

样例 1 专门检查循环方向。从前往后算会得到 `[0.86, 0.7592, 1.9466]`，动画最后一帧画了这个错误。

## 思路

先算出每一步的 δ，再从最后一步往前走，用 `A_t = δ_t + γλ · A_{t+1}` 一步一步推。只需要一个变量记住后一步的优势。

### 先看懂 δ

δ 叫 TD 误差，表示“这一步比预期好多少”。看最后一步：价值网络估计 t = 2 的状态值 0.6。实际这一步拿到 2 分，之后轨迹结束，未来估值是 0。所以 δ₂ = 2 + 0.9 × 0 − 0.6 = 1.4。

t = 1 拿到 0 分，下一个状态估值 0.6，打 0.9 折是 0.54。0 + 0.54 − 0.4 = 0.14，只比预期好一点。t = 0：1 + 0.9 × 0.4 − 0.5 = 0.86。

δ 只往后看一步，剩下的全靠估值。估值不准，δ 就有偏差。

### 把后面的 δ 也加进来

GAE（广义优势估计）把后面各步的 δ 也加进来，越远打折越多。展开写就是

`A_0 = δ_0 + (γλ)·δ_1 + (γλ)²·δ_2`

这里 γλ = 0.9 × 0.8 = 0.72。代入：0.86 + 0.72 × 0.14 + 0.5184 × 1.4 = 0.86 + 0.1008 + 0.72576 = 1.68656。

每一步都这样展开求和要 O(T²)。但 A₁ = δ₁ + 0.72·δ₂，所以 A₀ = δ₀ + 0.72·A₁，知道 A₁ 就能一步算出 A₀。A₁ 依赖 A₂，A₂ 依赖“终点之后”的 0。依赖从右指向左，所以循环必须**从最后一步往前走**，用变量 `running` 记住后一步的优势。

### 两个检查答案的办法

λ 取 0 或 1 时，答案可以另外算出来，用来验证代码。

- `lam = 0`：γλ = 0，后面的 δ 全被乘成 0，A 就等于 δ，即 `[0.86, 0.14, 1.4]`。
- `lam = 1`：δ 里的估值项两两抵消，A_t 等于“从 t 开始的折扣回报”减去 V_t。t = 0 的折扣回报是 1 + 0.9 × 0 + 0.81 × 2 = 2.62，减去 0.5 得 2.12；t = 1 是 0 + 0.9 × 2 = 1.8，减 0.4 得 1.4；t = 2 是 2 − 0.6 = 1.4。

λ 越接近 1，越相信真实奖励，偏差小、方差大。越接近 0，越相信价值网络，方差小，但估值不准时偏差大。常见取值是 0.95 左右。

训练价值网络时，目标值通常取 A + V。这个样例里是 `[2.18656, 1.548, 2.0]`。

## 复杂度

T 是轨迹的步数。

- **时间 O(T)**：每一步算一次 δ、一次 A，都是常数次乘加。
- **空间 O(T)**：用来存放返回的优势列表。除此之外只有 `running` 一个变量，额外空间 O(1)。

样例 1 的正确答案是 `[1.68656, 1.148, 1.4]`。

如果你得到 `[0.86, 0.7592, 1.9466]`，循环是从前往后跑的，每一步加上的是前一步的优势。

如果你得到 `[1.5368, 1.04, 1.4]`，是把 γλ 也用到了 δ 里，写成了 `r + gamma * lam * V_next − V`。δ 里只有 γ，λ 只出现在累加 A 的那一步。
</Aside>

本页代码还测过：空轨迹、只有一步、`gamma = 0`（结果是 `[0.5, −0.4, 1.4]`，即奖励减估值）、随机 12 步轨迹与“按定义逐项求和”的写法对拍，以及长度不一致和 `gamma` 越界两种非法输入。

## 延伸：轨迹是被步数上限截断的，`last_value` 填什么？

假设环境规定最多走 3 步。第 3 步结束时任务还没完成，只是被强行停下，后面本来还有奖励。

代码不用改，只改输入：`last_value` 填价值网络对第 3 步之后那个状态的估值，比如 0.5，而不是 0。δ₂ 变成 2 + 0.9 × 0.5 − 0.6 = 1.85，往前推：A₁ = 0.14 + 0.72 × 1.85 = 1.472，A₀ = 0.86 + 0.72 × 1.472 = 1.91984。整组优势是 `[1.91984, 1.472, 1.85]`。

如果把截断当成终点、仍填 0，三个优势都会偏小。

多条轨迹首尾相接放在一个数组里时，遇到真正的终点，要把下一状态的估值和 `running` 一起清零。否则前一条轨迹会把后一条的 δ 累加进来。

对比 <ProblemLink slug="grpo-advantage" />：GRPO 不训练价值网络，用同一个问题多次采样的组内平均分代替 V，所以没有 δ 和这一步倒序累加。算出的优势交给 <ProblemLink slug="ppo-clip" /> 里的裁剪目标使用。
