## 题目

实现 BPE（字节对编码）训练中的一轮合并 `merge_once(rows, new_id)`：找出最常相邻出现的一对 token，把它换成新 token `new_id`。

输入 `rows` 是若干行语料，每行是 `(token 列表, 词频)`。token 是非负整数，词频是这一行在语料里出现的次数。`new_id` 是没用过的新 ID。

1. 计票：一行里每出现一次相邻对 `(a, b)`，就给它加上这行的词频。相邻位置可以重叠，`[1, 1, 1]` 里算两对 `(1, 1)`。票数最高的数对胜出；并列时取字典序最小的（先比 `a` 再比 `b`，按数值比）。
2. 替换：每行从左到右扫描，把胜出数对换成 `new_id`。一个 token 只能合并一次，替换互不重叠。词频不变。

- 返回 `(胜出的数对, 新的各行)`。
- 所有行都短于 2 个 token 时，返回 `(None, 原来的 rows)`。
- 词频不是正整数时，抛 `ValueError`（TypeScript 抛 `Error`）。

## 样例

四个样例的 `new_id` 都是 9。

| 输入 `rows` | 返回 |
|---|---|
| `[([1,1,1], 2), ([1,2], 3)]` | `((1,1), [([9,1], 2), ([1,2], 3)])` |
| `[([1,2,3], 1), ([2,3,1,2], 1)]` | `((1,2), [([9,3], 1), ([2,3,9], 1)])` |
| `[([1,1,1,1], 1)]` | `((1,1), [([9,9], 1)])` |
| `[([5], 3), ([], 2)]` | `(None, [([5], 3), ([], 2)])` |

样例 1 防替换时重叠：`[1, 1, 1]` 只能变成 `[9, 1]`，不能变成 `[9, 9]`。样例 2 里 `(1, 2)` 和 `(2, 3)` 都是 2 票，按字典序取 `(1, 2)`。

## 思路

一轮分两遍：**先计票选出赢家，再单独扫一遍做替换**。计票时一个 token 可以属于两个相邻对，替换时一个 token 只能用一次。

### 计票：每个相邻位置都算

逐行扫描相邻位置，每找到一对就加上这一行的词频。

第 0 行 `[1, 1, 1]` 的词频是 2。下标 0、1 是 `(1, 1)`，下标 1、2 也是 `(1, 1)`，所以 `(1, 1)` 得 2 + 2 = 4 票。第 1 行 `[1, 2]` 的词频是 3，`(1, 2)` 得 3 票。4 > 3，`(1, 1)` 胜出。

计票问的是“这两个 token 多常挨在一起”，不是“实际能合并几次”，所以允许重叠。两个数可以不同：`(1, 1)` 拿了 4 票，替换后每份 `[1, 1, 1]` 里只有一个 9，语料里一共只合并了 2 次。

### 选赢家：票数相同看字典序

样例 2 的票数：

- `(1, 2)`：第 0 行 `[1, 2, 3]` 一次，第 1 行 `[2, 3, 1, 2]` 末尾一次，共 2 票。
- `(2, 3)`：两行各一次，共 2 票。
- `(3, 1)`：只在第 1 行出现一次，1 票。

`(1, 2)` 和 `(2, 3)` 并列，比第一个数，1 < 2，取 `(1, 2)`。替换后第 0 行是 `[9, 3]`，第 1 行是 `[2, 3, 9]`。

Python 里一句 `min(counts, key=lambda p: (-counts[p], p))` 就够了：票数取负后，票越多值越小，先被 `min` 选中；元组按位比较就是字典序。

### 替换：从左到右，用掉就跳过

用一个下标 `i` 从左往右走：

- 如果 `tokens[i]` 和 `tokens[i + 1]` 正好是胜出的数对，输出 `new_id`，`i` 加 2，跳过这两个 token。
- 否则原样输出 `tokens[i]`，`i` 加 1。

`[1, 1, 1]`：`i = 0` 时匹配，输出 9，`i` 跳到 2；`i = 2` 时后面没有 token 了，输出 1。结果 `[9, 1]`。

`[1, 1, 1, 1]`：`i = 0` 匹配，输出 9，跳到 2；`i = 2` 又匹配，输出 9。结果 `[9, 9]`，四个 1 恰好两两配对。

从左往右是约定，和 Hugging Face 等常见实现一致。从右往左扫，`[1, 1, 1]` 会变成 `[1, 9]`，也不重叠，但切分不同，所以题目要规定一种。

TypeScript 版有两处要多写几句：

- 计票用的 `Map` 不能直接拿数组 `[a, b]` 当键。`Map` 按引用比较数组，两个内容相同的数组是两个不同的键，票数永远是 1。这里把数对拼成字符串 `"a,b"` 当键。
- 选赢家时要把键拆回数字再比较。直接比较字符串，`"10,2"` 会排在 `"9,3"` 前面，因为字符 `1` 小于 `9`。测试里专门有一条：`(9, 3)` 和 `(10, 2)` 各 1 票，正确答案是 `(9, 3)`。

Python 用 `Counter` 以元组作键，元组按内容比较，没有这两个问题。

## 复杂度

L 是所有行的 token 总数，R 是行数，P 是不同数对的个数（P ≤ L）。

- **时间 O(L + R)**：计票每个相邻位置一次字典操作（平均 O(1)），选赢家扫一遍 P 个数对，替换每个 token 最多看一次。每行至少要访问一次，所以有 R 这一项，空行也要原样放进结果。
- **空间 O(L + R)**：计票表最多 P 项，新的各行总长不超过 L。

<Aside type="caution" title="三个输入，看看你的答案">
`[([1,1,1], 2), ([1,2], 3)]` 应该得到 `[([9,1], 2), ([1,2], 3)]`。如果第一行变成了 `[9, 9]`，你把计票时找到的位置直接拿去替换了，中间的 1 用了两次。

`[([1,2,3], 1), ([2,3,1,2], 1)]` 应该选 `(1, 2)`。如果选了 `(2, 3)`，并列时你取的是先遇到的或后遇到的，而不是字典序最小的。

`[([10,2], 1), ([9,3], 1)]` 应该选 `(9, 3)`。如果选了 `(10, 2)`，你在按字符串比较数对。
</Aside>

## 延伸：编码一段新文本时，还要重新计票吗？

训练时反复调用上面的函数，每轮学到一条合并规则。对样例 1 的语料连续做三轮：

1. `(1, 1)` 4 票，合并成 9。语料变成 `[([9,1], 2), ([1,2], 3)]`。
2. `(9, 1)` 2 票，`(1, 2)` 3 票，`(1, 2)` 合并成 10。语料变成 `[([9,1], 2), ([10], 3)]`。
3. 只剩 `(9, 1)`，合并成 11。

学到的合并表按顺序是 `(1,1)→9`、`(1,2)→10`、`(9,1)→11`。

现在要编码一段新文本 `[1, 2, 1, 1, 2]`。如果对这段文本重新计票，`(1, 2)` 有 2 票，`(2, 1)` 和 `(1, 1)` 各 1 票，会先合并 `(1, 2)`，得到 `[10, 1, 10]`。

这是错的。编码时不计票，而是**按合并表的顺序**依次应用每条规则：

- 先用 `(1,1)→9`：`[1, 2, 1, 1, 2]` 中间的两个 1 合并，得到 `[1, 2, 9, 2]`。
- 再用 `(1,2)→10`：得到 `[10, 9, 2]`。
- 最后 `(9,1)→11`：没有匹配。结果 `[10, 9, 2]`。

两种做法结果不同。每段文本都按自己的票数合并的话，同一个词在不同句子里可能切得不一样，推理时的切分就和训练时对不上。合并表的顺序就是优先级：越早学到的规则，编码时越先用。

替换那一步的代码可以原样复用，只是外面换成按顺序遍历合并表。

<Solution slug="bpe-merge" file="followup" />

这样写的时间是 O(M·n)，M 是合并表的长度，n 是文本的 token 数。常见实现会反过来做：每次在当前序列的相邻对里找合并表中排名最靠前的一对，只处理真正出现过的规则。两种写法结果相同，因为后学到的规则产生的新 token 不会出现在更早的规则里。
